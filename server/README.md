# NLP-HAZOP

A research prototype for recovering missing endpoints in structured HAZOP causal relationships. The system compares prompt-only LLM reasoning, sparse vector retrieval, graph reasoning, and a hybrid graph + vector + LLM strategy.

> **Research caveat:** the benchmark labels currently available in this repository are row-derived *silver associations*. They are not independently expert-validated causal ground truth. Report results as exploratory recovery of worksheet associations, not proof of causal correctness or plant safety.

## Research methods

| Method | Implementation | Input available to method | Output |
|---|---|---|---|
| Prompt-only LLM | PromptOnlyReasoner | Held-out scenario metadata and query only | Model-inferred endpoint or abstention |
| Vector retrieval | TfidfRetriever | Training-corpus records indexed with sparse TF–IDF | Ranked row-associated endpoint candidates |
| Graph reasoning | GraphReasoner + GraphNeighborhoodRetriever | Typed causal edges from training scenarios in the same plant/process family | Direct evidence candidate or bounded multi-hop path hypothesis |
| Hybrid | HybridRetriever + HybridReasoner + LLMReasoner | TF–IDF candidates plus graph-derived path candidates | LLM adjudication with provenance-aware evidence |

The vector baseline is a transparent **TF–IDF sparse-vector** implementation. It is not a dense embedding model and does not use Qdrant. The graph implementation uses the repository abstraction and an in-memory adapter; Neo4j persistence is not required to reproduce these experiments.

### Provenance model

Relationships carry an explicit origin:

- source: directly attributed to a source.
- reconstructed: reconstructed from a published case; not verbatim source rows.
- synthetic: generated/simulated scenario data; not source evidence.
- expert: explicitly expert-validated.
- retrieval_inferred: candidate generated by retrieval from row co-occurrence.
- graph_inferred: indirect path hypothesis composed from graph edges.
- model_inferred: model-only proposal.

The supplied T-301 and DWSIM datasets contain no expert-validated records. The loader therefore keeps all records UNREVIEWED; strings such as “Review required” or “Scope caveat” are retained as notes and never treated as successful validation.

## Datasets

Datasets are stored separately and benchmarked separately.

| Track | File | Rows | Provenance |
|---|---|---:|---|
| T-301 reconstructed | data/raw/t301/T301_HAZOP_CCPS2001_style.csv filtered to PAPER_REPORTED_RECONSTRUCTION | 40 | Reconstructed from the reported T-301 case in Single et al. (2020); not a verbatim transcription |
| T-301 synthetic | Same file filtered to SYNTHETIC_CONTINUATION | 54 | Synthetic continuation; not attributable to the paper |
| DWSIM synthetic | data/raw/dwsim/synthetic_hazop_D001_D030.csv | 30 | Synthetic/simulation-derived scenarios; review and scope caveats remain |

data/raw/dwsim/HAZOP_DWSIM30_worksheet_format.csv is a worksheet-style export of the D001–D030 synthetic DWSIM scenarios. It is an alternate representation, not an additional independent set of 30 scenarios. The canonical benchmark input is synthetic_hazop_D001_D030.csv.

The DWSIM validation-note values present in the source are retained in record remarks: 16 “Review required”, 6 “Scope caveat”, 6 “NEEDS_MODEL_REVISION”, 1 “Review reaction model”, and 1 “NEEDS_REVIEW”. None is silently promoted to expert validation.

### Graph construction from a row

The importer maps row fields into typed edges:

- cause --causes_deviation--> deviation
- If a simulated/inferred effect is present: deviation --leads_to--> effect --leads_to_consequence--> consequence
- Otherwise: deviation --leads_to_consequence--> consequence

These edges preserve the row origin and source/scenario identifier. Their evidence text states that they are row-level associations, not independent causal validation. A composed path is returned with origin graph_inferred, the full path, and no fabricated confidence value.

## Leakage-aware benchmark

The runner performs a deterministic **scenario-level** train/test split (default 80/20, seed 42). All queries derived from a scenario stay in the same split.

For held-out scenarios, the retrieval repository contains a metadata-only record. Causes, consequences, safeguards, recommendations, remarks, and causal edges are removed from that target record. Graph neighbourhoods and TF–IDF indices are built from training scenarios only. The target row is used only to construct its query and silver answer set.

One query is created for each listed cause in a held-out row. The answer set contains the consequences co-listed in that same row. Since the source rows do not specify independently adjudicated cause-to-consequence pairs, all co-listed consequences are treated as candidate silver endpoints for each cause. This definition is explicit in output metadata and must not be described as expert ground truth.

### Metrics

The output reports:

- Micro and macro precision, recall, and F1.
- Hit@1 and mean reciprocal rank (MRR).
- Coverage and abstention rate.
- Mean number of candidates.
- Evidence-text availability and provenance-origin rates.
- Mean per-query latency and TF–IDF index-build time.
- cost_usd, left null because the current Groq wrapper does not capture billable token usage reliably.

LLM methods use the same deterministic capped query subset (max-llm-cases) to limit API calls. If GROQ_API_KEY is unavailable, the prompt-only and hybrid methods are marked skipped; the script does not substitute fake model outputs.

## Setup

From the server/ directory:

~~~bash
uv sync
~~~

Set the Groq key only when running LLM methods. Keep .env out of version control:

~~~bash
# server/.env
GROQ_API_KEY=your_groq_api_key
~~~

## Reproduce the benchmark

Run each dataset as a separate experiment:

~~~bash
cd server
uv run python -m scripts.run_benchmark --dataset t301-reconstructed
uv run python -m scripts.run_benchmark --dataset t301-synthetic
uv run python -m scripts.run_benchmark --dataset dwsim-synthetic
~~~

Enable prompt-only and hybrid LLM calls (requires GROQ_API_KEY):

~~~bash
uv run python -m scripts.run_benchmark \
  --dataset t301-reconstructed \
  --with-llm \
  --max-llm-cases 10
~~~

Useful controls:

- --test-fraction 0.2
- --seed 42
- --top-k 10
- --max-hops 4
- --limit-cases 20 for a quick smoke run
- --output-dir results/custom-run

Each run writes:

- results.json: metadata, per-method aggregate metrics, and per-case predictions.
- summary.csv: compact method comparison.
- predictions.csv: one row per query and method.

Generated results are intentionally not committed as canonical research findings until the user reviews the run, confirms the split and labels, and (for causal correctness claims) supplies expert-adjudicated ground truth. GitHub Actions runs the test suite and all three non-LLM tracks, then uploads their output files as a workflow artifact.

## Current limitations and next research requirements

1. **Silver-label limitation:** row co-occurrence cannot establish that every listed cause produces every listed consequence. Expert adjudication is required before claiming causal correctness.
2. **Dataset limitation:** T-301 has only 40 reconstructed and 54 synthetic rows; DWSIM has 30 synthetic scenarios. Do not pool them, and do not train or evaluate a large model on these small data as if they were representative.
3. **Vector limitation:** TF–IDF is lexical and does not provide semantic embeddings. A dense embedding + vector database comparison is a separate future experiment and should be reported as such.
4. **Graph limitation:** paths compose typed cause/deviation/effect/consequence edges. They express indirect reachability, not proof that the endpoints form a direct causal edge.
5. **LLM limitation:** outputs are model-inferred and may abstain; confidence is model-reported, not calibrated probability. API latency is measured, but token cost is not yet captured.
6. **Validation still required:** have HAZOP experts adjudicate a held-out subset, define relation-level evidence criteria, measure annotation agreement, and report performance on expert-validated labels separately from synthetic/reconstructed silver labels.
7. **Safety boundary:** this is a research aid, not an operational HAZOP tool or safety recommendation generator. Engineering decisions require qualified review.
